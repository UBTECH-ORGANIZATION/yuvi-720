# מפת האקטיביות — איך מחושבת מגמת עלייה/ירידה

מסמך זה מתאר איך שישה תחומי האקטיביות בלוח התלמיד מקבלים ציון, איך נקבעת
מגמת העלייה/הירידה (החץ הירוק/אדום על האמבלמה), ואיך נבחר הטקסט שמסביר לתלמיד
*למה* התחום זז.

קוד מקור:
[`backend/app/brain/activeness.py`](../../backend/app/brain/activeness.py) ·
[`frontend/src/features/student-dashboard/ActivenessWeb.tsx`](../../frontend/src/features/student-dashboard/ActivenessWeb.tsx)

---

## 1. מתי החישוב רץ

בכל קריאה ל‑`GET /api/brain/{learner_id}/dashboard`. אין קאש ואין משימה מתוזמנת —
הציון מחושב מחדש בכל טעינה של הלוח.

הקלט:

| מקור | מה נלקח ממנו |
|---|---|
| `learning_events` | אירועי xAPI אמיתיים של הלומד/ת |
| `tutor_decisions` | רמזים והסברים שהמערכת נתנה |
| `brain.profile.activeness` | ציון הבסיס מתוך שאלון המיפוי הראשוני |
| `brain.mastery` | מצב שליטה ביעדים (צורך חזרה, רצף הצלחות) |
| `brain.reflections_recent` | רפלקציות שהלומד/ת כתב/ה |

האירועים נשלפים לפי **טווח זמן** ולא לפי מספר שורות — `EVIDENCE_SPAN_DAYS = 28`
יום. זה קריטי: שליפה מוגבלת במספר שורות מחזירה את החדשים ביותר, וכך מוחקת בדיוק
את השבוע שאליו משווים.

## 2. איך נבנה הציון

```
value = base + clamp( confidence × GAIN × Σ points , −MAX_DRIFT , +MAX_DRIFT )
```

| קבוע | ערך | משמעות |
|---|---|---|
| `GAIN` | 0.45 | המשקל המרבי של ההתנהגות האחרונה |
| `MAX_DRIFT` | 28 | תקרת התזוזה מציון הבסיס |
| `EVIDENCE_FULL` | 12 | כמות ראיות לביטחון מלא |
| `WINDOW_DAYS` | 21 | חלון הקריאה של האותות |

כלומר **ציון הבסיס מהשאלון תמיד שומר על לפחות 55% מהמשקל**, וההתנהגות יכולה
להזיז תחום ב‑28 נקודות לכל היותר. הציון נחתך בסוף לטווח 0–100.

---

## 3. איך נקבעת המגמה

המנוע מריץ את **אותו חישוב פעמיים**, בשתי נקודות זמן:

| הרצה | חלון |
|---|---|
| `m` (עכשיו) | 21 הימים האחרונים |
| `prior` (לפני שבוע) | 21 יום שמסתיימים לפני 7 ימים |

`prior_value` הוא הציון של ההרצה השנייה, לפי אותה נוסחה בדיוק. המגמה היא
`value − priorValue`.

> זה **לא** "מה מצבי" אלא **הפרש בין שתי נקודות זמן**. לכן תחום יכול לרדת גם
> כשכל האותות הנוכחיים נראים טובים — המספרים של היום לא מכילים את ההסבר לירידה,
> רק ההשוואה מכילה אותו.

## 4. ששת התחומים

שני גדלים משותפים:

```
regularity      = clamp(active_days / (21 × 0.4), 0, 1)     # ≈8.4 ימים = מלא
completion_rate = clamp(completions / objectives, 0, 1)
```

### מוטיבציה ורלוונטיות
נוכחות, סקרנות וסיום מה שהתחלת.

| אות | תרומה | נקודת האיזון |
|---|---|---|
| `inconsistent` | `(regularity − 0.5) × 40` | ~4.2 ימי פעילות |
| `low_engagement` | `(completion_rate − 0.5) × 22` | 50% סיום |
| `low_engagement` | `clamp((n − 4) / 8, ±0.5) × 12` | 4 אירועים מדורגים |

### תפיסת צמיחה
היכולת לחזור ולנסות אחרי טעות.

| אות | תרומה |
|---|---|
| `quits_on_fail` | `(recovery_rate − 0.5) × 44` |
| `quits_on_fail` | `(success_rate − 0.55) × 16` |
| `low_engagement` | `(clamp(avg_streak / 3, 0, 1) − 0.4) × 14` |

`recovery_rate` = מתוך היעדים שנכשלו, בכמה הייתה אחר כך הצלחה.

### יוזמה ואחריות
הנעה עצמית, ניסיון לפני רמז, סיום משימות.

| אות | תרומה | הערה |
|---|---|---|
| `low_engagement` | `(completion_rate − 0.5) × 30` | |
| `hint_reliance` | `−clamp(hint_rate − 0.4, 0, 0.6) × 26` | **קנס בלבד** — לא מזכה |
| `low_engagement` | `clamp((active_days − 3) / 6, ±0.4) × 12` | |

### ויסות עצמי
קצב, ריכוז והיצמדות לחזרות.

| אות | תרומה | הערה |
|---|---|---|
| `guessing` | `(0.5 − guess_rate) × 40` | ניחוש = תשובה מדורגת מתחת ל‑3.5 שניות |
| `guessing` | `(0.4 − review_ratio) × 20` | |
| `hint_reliance` | `−clamp(hint_rate − 0.6, 0, 0.4) × 24` | **קנס בלבד** |

### מודעות עצמית
עצירה לרפלקציה, זיהוי מה עוזר לי.

```
refl_rate = clamp(reflections / max(1, completions or objectives), 0, 1)
```

| אות | תרומה |
|---|---|
| `low_reflection` | `(refl_rate − 0.4) × 44` |
| `low_reflection` | `−10` נוסף אם אין אף רפלקציה ויש ≥2 סיומים |

הרפלקציות נספרות **רק בתוך החלון**. אין נפילה לספירה כוללת — אחרת מי שהפסיק/ה
לכתוב רפלקציות היה מקבל קרדיט על רפלקציות שלא כתב/ה.

### תמיכה וחוויה רגשית
בקשת עזרה בריאה וחיבור.

| אות | תרומה | הערה |
|---|---|---|
| `isolation` | `+clamp(hint_rate, 0, 0.5) × 34` | **בקשת עזרה כאן היא חיובית** |
| `isolation` | `−16` אם יש ≥2 כשלונות ואף בקשת עזרה | |
| `isolation` | `clamp((active_days − 2) / 6, ±0.3) × 10` | |

## 5. ביטחון (confidence)

```
confidence = clamp(evidence / 12, 0, 1)
```

כמות הראיות שונה בין התחומים, כי לא כל אירוע רלוונטי לכל תחום:

| תחום | ספירת ראיות |
|---|---|
| תפיסת צמיחה | `failed_objs × 3 + n` |
| מודעות עצמית | `reflections × 3 + completions` |
| תמיכה וחוויה רגשית | `n_hint × 3 + n` |
| שאר התחומים | `n` (אירועים מדורגים) |

מתחת ל‑`MIN_CAUSE_CONF = 0.3` המערכת **לא טוענת שום סיבה התנהגותית**. עדיף
שקט מאשר להאשים ילד/ה על סמך אירוע בודד.

## 6. איך נבחר טקסט ההסבר

זה החלק שהכי קל לטעות בו. `_drivers` **לא מתאר מצב נוכחי** — הוא מסכם את
התרומות לפי אות בשתי ההרצות ומחשב הפרש:

```
delta_tag = now_agg[tag] − prior_agg[tag]
```

* נשמרים רק אותות שזזו לפחות `MOVED_POINTS = 0.75` נקודות
* הכיוון הוא `up` אם ההפרש חיובי, אחרת `down`
* הרשימה ממוינת לפי גודל התזוזה

בצד הלקוח, `driverFor` בוחר את **הדרייבר הראשון שכיוונו זהה לכיוון החץ**. זה
מונע את המצב שבו ירידה מלווה בכיתוב "סיימת את מה שהתחלת". הטקסט עצמו הוא מפתח
תרגום `actmap.why.{tag}.{dir}`:

| אות | עלייה | ירידה |
|---|---|---|
| `inconsistent` | נכנסת ללמוד כמעט כל יום השבוע. | היו כמה ימים שלא נכנסת ללמוד. |
| `low_engagement` | סיימת את הפעילויות שהתחלת. | נשארו פעילויות שהתחלת ולא סיימת. |
| `quits_on_fail` | אחרי טעויות חזרת וניסית שוב. | אחרי טעות היה קשה לחזור ולנסות שוב. |
| `hint_reliance` | ניסית בעצמך לפני שפתחת רמז. | פתחת רמזים לפני שניסית בעצמך. |
| `guessing` | לקחת זמן לקרוא ולחשוב לפני שענית. | היו הרבה תשובות מהירות מדי. |
| `low_reflection` | עצרת בסוף שיעורים וכתבת מה עזר לך. | כמעט לא עצרת לכתוב מה עזר לך. |
| `isolation` | ביקשת עזרה כשנתקעת. | נתקעת כמה פעמים ולא ביקשת עזרה. |

אם אין דרייבר תואם, מוצג `actmap.change.fallback`:
"שמנו לב שמשהו זז כאן — נגלה יחד למה תוך כדי."

### שיוך לשיעור

שם השיעור נוסף (`actmap.why.inLesson`) רק עבור `low_engagement`,
`quits_on_fail` ו‑`guessing:down`. `_attribute` מחזיר `None` לשאר האותות
במכוון — נוכחות סדירה או רפלקציה הן עניין של השבוע ולא של שיעור מסוים, ולנקוב
בשם שיעור שם זה ניחוש שמחופש לראיה.

### מעבר לצ'אט

בירידה בלבד מוצג כפתור "לשאול את יובי למה", שפותח את הצ'אט הרגיל מצד המסך עם
השאלה של הלומד/ת. כשידוע השיעור, השאלה מציינת אותו.

## 7. מתי בכלל מוצג משהו

ארבעה שערים, וכולם חייבים להתקיים:

1. `confidence ≥ 0.3` — אחרת אין דרייברים בכלל
2. **שער הפער בנתונים** — אם בחלון הקודם אין ראיות *וגם* קיימת היסטוריה ישנה
   יותר, `prior_value` מושווה ל‑`value` והדרייברים מנוקים. תקלה בקליטת
   הנתונים לא תדווח ללומד/ת כשיפור.
3. `evidenceBacked` חייב להיות אמת
4. `|delta| ≥ CHANGE_THRESHOLD = 4` — מתחת לזה אין תג, אין חץ ואין הסבר.
   מ‑`MAJOR_CHANGE = 10` התזוזה מצוירת כשינוי משמעותי.

## 8. מגבלות ידועות

* **סף מול דילול.** החלונות של 21 יום חופפים ב‑14 יום, כך שתזוזה אמיתית של
  שבוע מדוללת לכשליש לפני שהיא נמדדת מול סף של 4 נקודות. בפועל ההסבר נדלק
  לעיתים נדירות.
* **אותות ללא היסטוריה.** `review_ratio` ו‑`avg_streak` נקראים ממצב השליטה
  העדכני, שאין לו היסטוריה יומית — לכן הם זהים בשתי ההרצות ולעולם לא תורמים
  לתזוזה.
* **רמזים לא מוגבלים לחלון.** `n_hint` נספר מכלל ההחלטות ולא רק מתוך החלון.

שתי המגבלות האחרונות משתיקות תזוזה אמיתית; הן אינן יכולות ליצור טענה שקרית.
